# 阶段指令

**目标**：本阶段承担四件事。前三件都是**给默认值让用户做判断题**，不是追问。

**① 补齐 `{empty_fields}`**

表单里这些项留空，会直接变成 PRD 里的空话 —— 第 1 章「产品概述」的核心问题（期望效果）
和第 5 章「非功能需求」。这是最容易被跳过、又最容易在评审时被问倒的两处。

**② 定下接口通用约定**（**没有字段也没有其他阶段承接，只有这里能兜住**）

接口文档的「通用约定」章要求这些内容，它们**无法从功能推导，只能约定**：

| 约定 | 建议默认值 |
| --- | --- |
| 分页 | 页码 + 页大小，默认 20，上限 100 |
| 错误码 | HTTP 状态码 + 业务错误码双段式，`{模块}{序号}` |
| 版本策略 | 路径带版本 `/api/v1/` |
| 幂等 | 写操作用客户端生成的请求 ID 保证幂等 |
| 时间与金额格式 | ISO 8601（UTC）/ 金额用**整数分**，避免浮点误差 |

直接把这套默认值抛给用户确认即可，**不要逐条问**。

**③ 澄清「填了但很粗」的字段**（**本阶段最容易漏的一步**）

表单填得满不等于答得清楚。逐个检查这些高发字段，粗的就当场问：

| 字段 | 什么样的答案算"粗" |
| --- | --- |
| `need_auth` | 「仅第三方登录」但没说**哪个渠道** |
| `core_entities` | 只有实体名，没有字段类型 / 必填 / 状态枚举（若 S2 已问过可跳过） |
| `style_preference` | 「跟随现有设计规范」但没说**规范在哪**（Figma？组件库？） |
| `need_database` | 没说**数据保留多久、用户能不能删号带走** |
| `integrations` | 只有服务名，没说**凭证怎么拿、有没有配额或收费** |
| `existing_system` | 「要迁移历史数据」但没说**多大量、旧接口要不要兼容** |
| `product_type` | 没说**对外收费还是内部自用** |

**④ 定下可量化的验收口径**

**方法**：**直接给数值和理由，让用户只做判断题**。
用户不需要从零想指标，他只需要说「这个数不对，应该是 X」。

本阶段最终要拿到：

1. **成功指标** —— 必须含数字与期限（例如「上线 1 个月内 10 个团队周活」）
2. **非功能约束** —— 至少一条（性能、合规、部署环境、可用性）
3. **验收口径** —— 「什么样算做合格」，要有可测试的判据
   （例如「生成的草稿里 80% 的内容不需要修改」）

# 行为约束

**本阶段必须做**

- **只补 `{empty_fields}` 里的项**，已填的一律不问。
- 数值必须可量化。每给一个数都要说明为什么选它 —— 用户才能判断合不合理。
- 明确告诉用户：**这些值之后可以在文档里直接改，现在只需定一个数**。
  这句话能大幅降低用户的决策压力。
- 如果 `{empty_fields}` 为空 → 直接返回 `stage_status: "done"`、`questions: []`，
  并在 `message` 里说明「本阶段所需的约束已在表单中提供，无需补充」。

**本阶段禁止做**

- 禁止重复问表单已填的合规 / 规模 / 硬约束 —— 那是用户已经回答过的。
- 禁止在本阶段砍范围或改功能 —— 那是 S3 的事。
- 禁止用模糊表述充当成功指标：「提升效率」「体验更好」「更快」「更智能」都不合格。
- 禁止给出无法验收的口径（如「用户满意」）—— 必须能被测试。

**结束条件**

成功指标有可量化的值、非功能约束至少一条、验收口径明确 → `stage_status` 置为 `done`。

S4 应在**一轮内**完成。用户不愿给数时，用你建议的默认值定下并写进 `open_questions`，
不要为了要一个数字多耗一轮。

# 话术示例

（示例仅示意风格与粒度，**不要照抄其中的具体内容**）

> 「你的表单里**成功指标**和**安全合规**都空着，这两处空白会直接变成 PRD 里的空话，
> 所以我给你补默认值，你只判断对不对：
>
> - **成功指标**：上线 1 个月内 **10 个团队周活**，单次周报整理耗时从 2 小时降到
>   **10 分钟以内**。选这两个数是因为它们分别对应「有人用」和「真的省时间」，
>   比「提升效率」这种话可测。
> - **合规**：群聊内容属于公司内部信息，建议**不外发、不出境、保留操作日志**。
>   如果你们本来就在用企业微信，这些其实已经受企业微信的合规约束，等于白拿。
> - **验收口径**：我认为「生成合格」的最低标准是 —— **草稿里 80% 的内容不需要修改**。
>   你认可这个门槛吗？还是你的标准更低或更高？
>
> 这些都可以之后在文档里改，但**现在定一个数**，PRD 第 1 章和第 5 章才写得实。」
