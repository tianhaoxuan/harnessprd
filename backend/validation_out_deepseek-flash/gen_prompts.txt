# 01 · 项目总控（群聊周报助手）

## 项目定位

群聊周报助手是效率工具（解决单点问题），平台形态为 Web 网站。要解决的问题：团队群聊里信息散落，每周要人工翻聊天记录拼周报，一次要花两小时，还容易漏掉重要进展。目标用户：20 人以下创业团队的技术负责人，兼做项目管理。

核心动线是一条单点闭环：选群 → 生成 → 改 → 导出。一次只处理一个企业微信群、一个时间范围（默认最近 7 天），点「生成」后约 30 秒得到按人分组的周报草稿，人工修改后复制到飞书群。

## 技术栈与目录结构

| 层 | 选型 |
| --- | --- |
| 前端 | React |
| 后端 | FastAPI |
| 数据库 | PostgreSQL |
| 接口风格与鉴权 | RESTful + JWT |
| 第三方服务 | 企业微信（拉取群消息）、GitHub OAuth（登录） |

前端按 features 分目录，即 `frontend/src/features/<feature-name>/`。后端目录结构本次输入未约定，`[待确认]`。

## 代码规范

- 接口入参必须校验。
- 提交前跑 lint + 测试。

## 视觉与交互约定

- 整体风格简洁克制，对齐 Linear / Notion：以内容和留白为主，低装饰。
- 周报生成期间页面必须显示「生成中」状态，时长约 30 秒。

## 数据约定

- 路径前缀 `/api/v1`，路径段与字段名用 `snake_case`，如 `report_id`、`group_id`、`group_by`。
- 枚举值用小写英文：`group_by` 取 `person` / `project`；登录 `provider` 取 `wecom` / `github`。
- 用户字段：id、昵称、所属团队；周报字段：id、周期、正文、状态、创建人。
- 周报状态包含「草稿」。
- 时间范围默认最近 7 天；周期边界算法 `[待确认]`。

## 错误处理约定

| 场景 | 约定 |
| --- | --- |
| 未登录访问周报接口 | 跳转第三方登录 |
| 成员访问他人周报 | 拒绝访问并提示无权限 |
| 群消息拉取失败 | 跳过该群并提示，不整体失败，可换群重试 |
| 时间范围内该群无消息 | 提示「该时间范围内无消息」，不生成草稿 |
| 生成失败 | 保留已拉取的消息，提示可重试 |
| 保存失败 | 保留用户本地已输入内容，提示重试 |
| 导出时正文为空 | 禁止导出并提示 |

## 安全与合规约定

本次无该维度输入，待补充。

## 硬性禁止事项

- 不做跨群汇总，一次只处理一个群。
- 不做实时同步，仅按用户触发生成。
- 不自建账号体系，仅企业微信 / GitHub 第三方登录。
- 不做历史数据迁移（全新项目）。
- 正文少于 5 字或纯表情的消息不进周报。
- 某人本周无有效消息，不出现在周报里。
