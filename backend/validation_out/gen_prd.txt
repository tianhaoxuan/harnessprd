## 第 6 章 核心场景与用户动线

本产品为效率工具，解决单点问题，动线为单角色单点操作。

**主场景动线**

1. 周一早上，技术负责人打开工具。
2. 选择一个企业微信群。
3. 选择时间范围，默认最近 7 天。
4. 点击生成。
5. 等待约 30 秒。
6. 得到按人分组的周报草稿。
7. 手动改两处。
8. 复制到飞书群。

**角色分层**

| 角色 | 可见范围 |
| --- | --- |
| 团队成员 | 只能看自己的周报 |
| 团队负责人 | 可查看全部人的周报 |

**边界情况**

| 情况 | 处理 |
| --- | --- |
| 消息少于 5 字或纯表情 | 不进周报 |
| 某人本周无消息 | 不出现在周报里 |
| 群消息拉取失败 | 跳过该群并提示，不整体失败 |

## 第 7 章 功能需求

### FR-01 自动汇总指定群聊的消息

- **描述**：按用户选定的企业微信群与时间范围，拉取该群消息并汇总，作为周报草稿的素材。
- **输入**：企业微信群标识、时间范围（默认最近 7 天）。
- **输出**：该群在时间范围内的消息集合，已按边界规则过滤。
- **边界条件**：
  - 空数据：时间范围内无消息时，汇总结果为空，不报错。
  - 失败：群消息拉取失败时，跳过该群并提示，不整体失败。
  - 超量：时间范围超出可拉取上限时，返回错误并提示调整范围 `[待确认]`。
  - 权限：仅可拉取当前用户有权限访问的企业微信群。
  - 时间与时区：时间范围按用户所在时区解释 `[待确认]`。
  - 授权撤销：企业微信授权失效时，提示重新授权，不整体失败。
- **优先级理由**：P0。没有消息汇总就没有周报素材，是全部下游功能的前提。

### FR-02 按人 / 项目生成周报草稿

- **描述**：基于汇总后的消息，生成按人分组的周报草稿。
- **输入**：FR-01 的汇总结果。
- **输出**：按人分组的周报草稿，状态为草稿。
- **边界条件**：
  - 空数据：某人本周无消息时，不出现在周报里。
  - 失败：生成失败时保留已汇总素材，允许重试。
  - 超量：单次生成的消息量超出上限时，返回错误并提示缩小时间范围 `[待确认]`。
  - 权限：成员只能生成并查看自己的周报；团队负责人可生成全部人的周报。
  - 重复：同一周期重复生成时，覆盖或新建由用户确认 `[待确认]`。
  - 并发与竞态：同一周期并发生成时，仅保留一次结果 `[待确认]`。
  - 数据一致性：草稿内容必须与所用汇总素材一致。
  - 版本与升级：生成规则变更后，已生成草稿不被改写。
- **优先级理由**：P0。这是产品的核心价值，直接决定「生成草稿中 80% 的内容不需要修改」这一验收口径能否达成。

### FR-03 人工修改周报草稿

- **描述**：用户对生成的周报草稿进行人工修改。
- **输入**：周报草稿、用户的修改内容。
- **输出**：修改后的周报草稿。
- **边界条件**：
  - 空数据：草稿为空时，允许直接写入内容。
  - 失败：保存失败时保留用户输入，允许重试。
  - 权限：成员只能修改自己的周报；团队负责人可修改全部人的周报。
  - 撤销：支持撤销未保存的修改 `[待确认]`。
  - 并发与竞态：同一草稿被并发修改时，后提交者需提示冲突 `[待确认]`。
  - 数据一致性：修改后内容与导出内容一致。
- **优先级理由**：P0。草稿必然需要人工校正，没有修改能力则无法交付可用周报。

### FR-04 导出周报

- **描述**：将修改后的周报导出，供复制到飞书群。
- **输入**：修改后的周报草稿。
- **输出**：可复制的周报内容。
- **边界条件**：
  - 空数据：草稿为空时，导出空内容并提示。
  - 失败：导出失败时提示，不丢失草稿。
  - 权限：成员只能导出自己的周报；团队负责人可导出全部人的周报。
  - 数值精度：导出内容与草稿逐字一致。
- **优先级理由**：P0。导出是动线的终点，决定周报能否真正被使用。

### FR-05 第三方登录

- **描述**：用户通过第三方登录（微信 / GitHub 等）进入工具。
- **输入**：第三方登录凭证。
- **输出**：登录态。
- **边界条件**：
  - 失败：第三方登录失败时提示，不进入工具。
  - 权限：登录后按角色确定可见范围。
  - 授权撤销：第三方授权失效时，提示重新登录。
- **优先级理由**：P0。仅第三方登录是唯一的进入方式。

### FR-06 周报长期保存

- **描述**：长期保存用户数据与周报，供后续查看与导出。
- **输入**：用户数据、周报数据。
- **输出**：可查询的历史周报。
- **边界条件**：
  - 空数据：无历史周报时，返回空列表。
  - 失败：保存失败时提示，不丢失用户输入。
  - 权限：成员只能查看自己的周报；团队负责人可查看全部人的周报。
  - 数据一致性：保存内容与用户提交内容一致。
- **优先级理由**：P0。周报需长期保存，否则无法回溯与复用。

### FR-07 角色可见性控制

- **描述**：按角色控制周报的可见范围与操作权。
- **输入**：用户角色、周报归属。
- **输出**：可见或不可见的判定结果。
- **边界条件**：
  - 权限：成员只能看自己的周报；团队负责人可查看全部人的周报。
  - 授权撤销：角色变更后，可见范围随之变更。
- **优先级理由**：P0。角色可见性是明确的业务约束，必须在首版生效。
