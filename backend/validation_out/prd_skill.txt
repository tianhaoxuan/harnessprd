## 1. 产品概述

| 项目 | 内容 |
| --- | --- |
| 产品名称 | 群聊周报助手 |
| 平台 | Web 网站 |

**核心问题**

团队群聊里的进展、决策、阻塞信息散落在聊天记录中，没有结构化沉淀。技术负责人每周需要人工翻聊天记录拼周报，一次约两小时，且容易遗漏关键信息。期望达到的效果是：把群聊消息自动汇总为按人 / 项目组织的周报草稿，负责人只需少量修改即可导出，把撰写耗时从约 2 小时降到 10 分钟以内。

**目标用户**

20 人以下创业团队的技术负责人，兼做项目管理。

**平台约束**

本期为 Web 网站，需处理浏览器登录态与账号密码注册登录；屏幕宽度按 1280 起设计。对话中曾提到可能要小程序，本期先做 Web，小程序形态 `[待确认]`。

## 2. 功能需求

### MVP 功能

| 编号 | 功能 | 说明 | 优先级 | 边界条件 |
| --- | --- | --- | --- | --- |
| FR-01 | 账号注册登录 | 用户以账号密码注册并登录，登录后获得 JWT 凭证；未登录用户只能看到登录页 | P0 | 凭证失效时跳回登录页；密码以哈希形式存储，不落明文 |
| FR-02 | 绑定群聊并汇总 | 绑定一个群聊并选定时间范围，触发汇总任务，返回该群聊在范围内的消息汇总结果 | P0 | 时间跨度超过 31 天时拒绝并提示；群聊在选定范围内没有任何消息时给出空态而不是空草稿；同一群聊并发触发两次汇总时第二次返回既有任务不新建 |
| FR-03 | 生成周报草稿 | 基于汇总结果，按人 / 项目生成周报草稿，草稿初始状态为 draft | P0 | 汇总任务 failed 时不出草稿，可人工触发重试，重试次数不限 |
| FR-04 | 导出到飞书 | 将周报草稿导出为飞书文档，导出成功后草稿状态置为 exported，并返回文档链接 | P0 | 飞书侧限流每分钟 5 次，需退避重试；导出失败时草稿回落到 editing |
| FR-05 | 人工编辑草稿 | 用户手工调整草稿措辞，进入编辑即置为 editing，保存后写回草稿 | P1 | 仅 owner 可编辑；member 只读自己被汇总到的条目，不能改他人草稿 |
| FR-06 | 导出历史记录 | 查看历史导出记录 | P1 | 仅展示与当前用户有关的记录 |
| FR-07 | 按项目维度组织草稿 | 草稿除按人组织外，支持按项目维度组织 | P2 | 暂无 |
| FR-08 | 多群对比 | 对多个群聊的汇总结果做对比 | P2 | 是否支持多群对比 `[待确认]` |

### 验收标准

| 编号 | 对应功能 | 验收标准 |
| --- | --- | --- |
| AC-01 | FR-01 | 给定未登录用户，当访问除登录页外的任意页面时，则跳转到登录页；给定已注册账号，当输入正确账号密码时，则登录成功并获得 JWT 凭证 |
| AC-02 | FR-02 | 给定已登录的 owner，当绑定群聊并选定不超过 31 天的时间范围后触发汇总，则 30 秒内能看到按人分组的草稿 |
| AC-03 | FR-02 | 给定选定时间范围超过 31 天，当触发汇总时，则拒绝并给出提示；给定群聊在范围内没有任何消息，当触发汇总时，则展示空态而非空草稿 |
| AC-04 | FR-02 | 给定同一群聊已有汇总任务在运行，当再次触发汇总时，则返回既有任务且不新建任务 |
| AC-05 | FR-03 | 给定汇总任务 succeeded，当生成周报草稿时，则草稿按人 / 项目组织且状态为 draft |
| AC-06 | FR-03 | 给定汇总任务 failed，当人工触发重试时，则重新执行汇总，重试次数不限 |
| AC-07 | FR-04 | 给定草稿处于 editing，当导出到飞书成功时，则草稿状态置为 exported 并返回文档链接，导出成功率 100%（含重试） |
| AC-08 | FR-04 | 给定飞书侧返回限流，当触发导出时，则按每分钟 5 次的限制退避重试；给定导出失败，则草稿状态回落到 editing |
| AC-09 | FR-05 | 给定 owner 打开草稿并开始手改，当进入编辑时，则草稿状态置为 editing；给定 member 访问他人草稿，则只能只读自己被汇总到的条目，不能修改 |
| AC-10 | FR-06 | 给定已登录用户，当打开导出历史页时，则只看到与自己有关的导出记录 |

## 3. 页面设计

### 页面列表

| 页面名 | 用途 | 路径 | 支撑功能 |
| --- | --- | --- | --- |
| 登录页 | 账号密码注册登录 | `/login` | FR-01 |
| 表单页 | 绑定群聊并选定时间范围，触发汇总 | `/setup` | FR-02 |
| 汇总进度页 | 查看汇总任务进度与结果 | `/aggregations/:id` | FR-02 |
| 周报草稿页 | 查看与编辑周报草稿，导出到飞书 | `/reports/:id` | FR-03、FR-04、FR-05、FR-07 |
| 导出历史页 | 查看历史导出记录 | `/exports` | FR-06 |

### 模块划分

- 登录页：登录 / 注册表单模块，负责账号密码输入与提交；错误提示模块，负责展示凭证错误等信息。
- 表单页：群聊绑定模块，负责选择或绑定群聊；时间范围选择模块，负责选定汇总范围并校验 31 天上限；触发模块，负责发起汇总任务。
- 汇总进度页：任务状态模块，负责展示 running / succeeded / failed 与重试入口；结果概览模块，负责展示消息数与空态。
- 周报草稿页：草稿正文模块，负责按人 / 项目展示草稿内容；编辑模块，负责手工调整措辞与保存；导出模块，负责触发导出到飞书并展示文档链接。
- 导出历史页：导出记录列表模块，负责展示与当前用户有关的导出记录。

### 关键交互

- 在登录页提交正确账号密码且校验通过，登录成功并跳转到表单页。
- 在表单页选定时间范围超过 31 天，拒绝提交并就地提示。
- 在表单页触发汇总且同一群聊已有任务在运行，返回既有任务并跳转到汇总进度页。
- 汇总任务 failed 时，在汇总进度页人工触发重试，重新执行汇总。
- 在周报草稿页开始手改，草稿状态置为 editing；保存后写回草稿。
- 在周报草稿页触发导出且飞书侧限流，按每分钟 5 次退避重试；导出成功则状态置为 exported 并展示文档链接，失败则回落到 editing。

## 4. 技术规格

### 认证与权限

认证方式：账号密码注册登录，接口鉴权采用 JWT。

| 角色 | 可见范围 |
| --- | --- |
| owner（群聊归属人） | 可绑定 / 解绑群聊、查看与自己有关的周报 |
| member | 只读自己被汇总到的条目，不能改他人草稿 |

未登录用户只能看到登录页。

### 数据与存储

数据实体：

- 用户：id、姓名、邮箱、密码哈希
- 群聊配置：id、名称、归属人
- 汇总结果：id、时间范围、消息数
- 周报草稿：id、汇总 id、正文、状态

持久化范围：长期保存用户数据，使用 PostgreSQL 存储用户与草稿。规模为单团队 20 人以内，消息量每天数百条。

### 前后端技术

前端 React + TypeScript，后端 Python FastAPI，数据库 PostgreSQL。前后端分离，接口先定契约再实现，关键路径补测试。

### 部署方式

部署在内网服务器，不上公有云，容器化部署。

### 外部依赖

飞书开放平台（导出周报文档），需要应用凭证由管理员配置。

## 5. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 汇总 500 条消息 30 秒内返回；单团队 20 人以内，消息量每天数百条 |
| 安全 | 手机号必须加密存储；需要操作审计日志；数据不能出境；接口采用 JWT 鉴权 |
| 可用性 | 服务可用性按工作时段 99% 要求；汇总任务 failed 可人工触发重试，重试次数不限 |
| 兼容性 | 支持 Chrome / Edge 最近两个大版本，屏幕宽度 1280 起 |
