# 群聊周报助手 · 项目总控

## 项目定位

面向 20 人以下创业团队的技术负责人（兼做项目管理）的 Web 工具。
把指定群聊在指定时间范围内的消息自动汇总，按人 / 项目生成周报草稿，
支持人工修改后导出到飞书。

核心价值：把每周约 2 小时的周报撰写时间省下来。

## 技术栈与版本

| 层 | 选型 | 版本 |
| --- | --- | --- |
| 语言 | TypeScript | 5.4+ |
| 运行时 | Node.js | 20 LTS |
| 后端框架 | Fastify | 4.x |
| 数据库 | PostgreSQL | 16 |
| 数据库访问 | `pg` 裸 SQL | 8.x |
| 前端框架 | React | 18.x |
| 前端构建 | Vite | 5.x |
| 测试 | Vitest | 1.x |

## 目录结构

```
.
├── src/
│   ├── server/
│   │   ├── routes/          # 路由定义，按资源分文件
│   │   ├── services/        # 业务逻辑
│   │   ├── repositories/    # SQL 访问层
│   │   ├── middleware/      # 鉴权、错误处理
│   │   └── app.ts           # Fastify 实例装配
│   ├── shared/
│   │   ├── errors.ts        # 错误码与统一错误体
│   │   ├── ids.ts           # ID 生成
│   │   └── time.ts          # 时间与时区处理
│   └── web/                 # 前端
├── migrations/              # SQL 迁移文件，按序号命名
├── tests/
└── package.json
```

## 代码规范

- 全部 TypeScript，`strict: true`，禁止 `any`。
- 字段命名统一 `snake_case`，与接口文档逐字一致。
- 数据库访问统一用 `pg` 裸 SQL，**禁止引入 ORM**。
- 每个路由处理函数只做参数校验与调用 service，业务逻辑写在 service。
- 所有 SQL 必须参数化，禁止字符串拼接。
- 时间一律以 ISO 8601 UTC 字符串在接口层传递，数据库用 `timestamptz`。

## 视觉与交互约定

- 单页应用，左侧导航 + 右侧内容区。
- 主色 `#1F6FEB`，中性灰阶，无阴影、无圆角超过 6px。
- 所有异步操作按钮在请求期间置为 disabled 并显示加载态。
- 错误提示统一用顶部横幅，文案取自接口返回的 `message` 字段。
- 空状态必须显式展示文案，不留白屏。

## 数据约定

- 时间：ISO 8601 + UTC，如 `2025-01-13T02:15:00Z`。
- 汇总时间范围按用户 `timezone` 解释，边界为 `[start_at, end_at)`。
- 分页：`page` 从 1 起，`page_size` 默认 20、上限 100。
- 分页响应固定为 `items` / `page` / `page_size` / `total`。
- 空值返回 `null`，不省略字段。
- ID 格式：`usr_` / `gcp_` / `agg_` / `rpt_` / `exp_` + 12 位小写字母数字。

## 错误处理约定

- 成功响应不套信封，直接返回资源对象或分页对象。
- 失败返回统一错误体：

```json
{
  "error_code": "AGG001",
  "message": "时间跨度超过 31 天，请缩小范围",
  "details": { "field": "end_at", "max_span_days": 31 }
}
```

- 状态码分界：`400` 请求不合法；`422` 业务校验不通过；`409` 状态或并发冲突。
- 错误码全集见接口文档第 5 章，**不得自造错误码**。

## 安全与合规约定

- 除 `POST /api/v1/auth/register` 与 `POST /api/v1/auth/login` 外，所有接口必须校验 `Authorization: Bearer <access_token>`。
- 令牌缺失或失效返回 `401` + `AUTH004`。
- 所有资源查询在服务端按当前登录用户强制过滤，**不接受客户端传入 `user_id`**。
- 跨用户访问返回 `403` + `AUTH005`。
- 密码只存哈希，任何响应不返回密码字段。

## 硬性禁止事项

- 禁止引入 ORM。
- 禁止自造错误码、字段名、接口路径。
- 禁止在成功响应外层加 `data` / `result` 信封。
- 禁止实现 PRD 第 5 章「本期明确不做」中的任何功能。
- 禁止跳过鉴权中间件。

## 术语表

| 术语 | 定义 |
| --- | --- |
| 群聊 | 团队日常沟通所在的聊天群 |
| 汇总结果 | 指定群聊在指定时间范围内的消息汇总 |
| 周报草稿 | 基于汇总结果按人 / 项目生成的、可人工修改的周报内容 |
| 导出 | 将周报输出到飞书，使其可在飞书中打开 |
| 技术负责人 | 20 人以下创业团队中兼做项目管理的技术负责人 |

## 实体与字段

严格按接口文档第 4 章建表，字段名逐字一致：

| 表 | 主键前缀 | 关键字段 |
| --- | --- | --- |
| `users` | `usr_` | `id`、`account`（唯一）、`password_hash`、`display_name`、`timezone`、`created_at`、`updated_at` |
| `group_chats` | `gcp_` | `id`、`user_id`、`name`、`external_chat_id`、`member_count`、`created_at`、`updated_at` |
| `aggregations` | `agg_` | `id`、`user_id`、`group_chat_id`、`start_at`、`end_at`、`status`、`message_count`、`items`、`failure_reason`、`created_at`、`updated_at` |
| `weekly_reports` | `rpt_` | `id`、`user_id`、`aggregation_id`（唯一）、`title`、`group_by`、`status`、`sections`、`version`、`is_edited`、`created_at`、`updated_at` |
| `exports` | `exp_` | `id`、`weekly_report_id`、`user_id`、`target`、`status`、`external_doc_url`、`content_snapshot`、`failure_reason`、`created_at` |

`aggregations.items` 与 `weekly_reports.sections` 用 `jsonb` 存储，默认 `'[]'::jsonb`。

## 实体关系

```
users 1 ──< group_chats
users 1 ──< aggregations >── 1 group_chats
users 1 ──< weekly_reports >── 1 aggregations
weekly_reports 1 ──< exports
```

## 枚举全集

| 枚举 | 取值 | 用于 |
| --- | --- | --- |
| `aggregations.status` | `pending` / `succeeded` / `failed` | 汇总状态 |
| `weekly_reports.group_by` | `person` / `project` | 组织维度 |
| `weekly_reports.status` | `draft` / `exported` | 草稿状态 |
| `exports.target` | `feishu` | 导出目标，本期固定 |
| `exports.status` | `pending` / `succeeded` / `failed` | 导出状态 |

全部用 `CHECK` 约束落库，不用 PostgreSQL 原生 enum 类型。

## 级联规则

- `group_chats.user_id` → `users.id`，`ON DELETE CASCADE`。
- `aggregations.user_id` → `users.id`，`ON DELETE CASCADE`。
- `aggregations.group_chat_id` → `group_chats.id`，`ON DELETE CASCADE`。
- `weekly_reports.user_id` → `users.id`，`ON DELETE CASCADE`。
- `weekly_reports.aggregation_id` → `aggregations.id`，`ON DELETE CASCADE`。
- `exports.weekly_report_id` → `weekly_reports.id`，`ON DELETE CASCADE`。
- `exports.user_id` → `users.id`，`ON DELETE CASCADE`。

## 索引

| 表 | 索引 | 类型 |
| --- | --- | --- |
| `users` | `account` | 唯一 |
| `group_chats` | `(user_id, external_chat_id)` | 唯一 |
| `aggregations` | `(user_id, group_chat_id, start_at, end_at)` | 唯一 |
| `weekly_reports` | `aggregation_id` | 唯一 |
| `weekly_reports` | `(user_id, created_at)` | 普通 |
| `exports` | `(weekly_report_id, created_at)` | 普通 |

`aggregations` 的唯一索引是 AC-09 的落地点：同一用户重复触发同一群聊同一时间范围的汇总时，`INSERT ... ON CONFLICT DO NOTHING` 后回读已有记录。

- 不写种子数据。测试数据由 `tests/data-layer.test.ts` 在事务中创建并回滚。

- 请求体字段：`account`（4–32，仅字母数字下划线）、`password`（8–64）、`display_name`（可选，1–32）、`timezone`（可选，IANA 时区名，缺省 `Asia/Shanghai`）。
- 注册响应只返回 `id` / `account` / `display_name` / `timezone` / `created_at`，**不返回任何密码字段**。
- 登录响应返回 `access_token` / `token_type`（固定 `Bearer`）/ `expires_in` / `user`。

- 参数类型或格式错误返回 `400` + `COMMON001`。
- 密码用 bcrypt 哈希后存 `password_hash`，禁止明文。
- 令牌用 JWT 签发，密钥取自 `TOKEN_SECRET`，有效期 604800 秒。
- 两个接口均支持 `Idempotency-Key` 请求头，相同 Key 24 小时内返回首次结果。
- 鉴权中间件挂在除注册、登录外的全部路由上。

## 涉及接口

- `POST /api/v1/aggregations`
- `GET /api/v1/aggregations/{aggregation_id}`

## 约束

- 两个接口均需登录，角色为技术负责人。
- 请求体：`group_chat_id`（必填，必须属于当前用户）、`start_at`（必填，ISO 8601 UTC，含）、`end_at`（必填，ISO 8601 UTC，不含，且晚于 `start_at`）。
- 响应字段：`id` / `group_chat_id` / `start_at` / `end_at` / `status` / `message_count` / `items` / `failure_reason` / `created_at` / `updated_at`。
- `items[]` 元素：`message_id` / `sender_name` / `sent_at` / `content` / `project_hint`（无法判定时为 `null`）。
- 时间跨度上限 31 天，超出返回 `422` + `AGG001`。
- `start_at` 不早于 `end_at` 返回 `422` + `AGG002`。
- `group_chat_id` 不存在或不属于当前用户返回 `404` + `AGG003`。
- 命中 0 条消息返回 `422` + `AGG004`，**不落库为空汇总结果**。
- 上游消息源不可用返回 `502` + `AGG005`，保留用户已选的群聊与时间范围，允许重试。
- 时间范围按用户 `timezone` 解释，边界为 `[start_at, end_at)`。
- 重复触发同一 `group_chat_id` 与同一 `[start_at, end_at)` 时，命中唯一索引并返回已有汇总结果，**不产生重复记录**。
- 支持 `Idempotency-Key`，相同 Key 24 小时内返回首次结果。
- 状态流转：`pending` → `succeeded` / `failed`。
- 跨用户读取返回 `403` + `AUTH005`。
- `message-source.ts` 是上游消息源的唯一入口，本步用固定桩数据实现，接口签名固定为 `fetchMessages(external_chat_id, start_at, end_at): Promise<Message[]>`。
