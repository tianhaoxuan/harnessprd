# 提示词套件生成：技能包工作流

本技能包补充**套件结构与写作规则**。多文件输出契约（`=== FILE: ===` 分隔行）、
生成范围规则由 system prompt 的规范给出（`gen_prompts.md`）—— 这里只说明怎么用本技能包。

## 输入

- `{prd_content}`：已通过评审的 PRD 全文，**必读**。
- `{api_content}`：接口文档全文（可选；为「（尚无）」时说明本次不带接口文档，
  步骤里的「涉及接口」按 PRD 的功能需求描述，**不要自己编接口路径**）。
- 可选：对话确认信息（`{known_info}`）、用户跳过的项（`{open_questions}`）、分片范围。

## 输出

按 `references/prompts-template.md` 的目录结构输出文件；本次要生成哪些文件由
`{generate_scope}` 决定，**只输出本次范围**。

## 规范的优先级

1. `references/prompts-template.md` —— 五类提示词（PROJECT-BRIEF / SCAFFOLD /
   DATA-LAYER / FEATURE / VERIFY）、目录与命名、每类的内容要点与字数上限、
   类别 4 每步的固定 7 项、使用顺序与步骤覆盖矩阵。**结构以它为准。**
2. `references/writing-rules.md` —— 套件级质量规则：覆盖完整、依赖无环、可判定、
   命名一致、无冗余，以及多文件输出与文件内容格式。

## 与两份上游产物的关系

套件是**消费** PRD 与接口文档的下游，不是重新设计一遍产品：

- 文件名、步骤编号、模块名、接口路径必须与上游**逐字一致**；
- 接口文档没给的服务端细节，不要自己编一个接口出来；
- 每条功能需求都要能落到某个实现步骤上（覆盖矩阵的用途），
  但**纯前端需求不需要接口** —— 不要为了凑覆盖给它们编接口。
