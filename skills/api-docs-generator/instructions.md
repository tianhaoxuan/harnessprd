# 接口文档生成：技能包工作流

本技能包补充**团队接口规范与参考示例**。文档的章节结构、每个接口的固定 8 项、
字数上限与输出格式由 system prompt 里的规范给出（`gen_api.md`）—— 这里不重复，
只说明本技能包提供的规范怎么用。

## 输入

- `{prd_content}`：**已通过评审的 PRD 全文**，本次生成唯一的事实来源。
- 可选：对话确认过的补充信息（`{known_info}` / `{open_questions}` / `{conflicts}`）。
- 可选：分片范围（`{generate_scope}` / `{scope_spec}`）—— 只输出本次范围内的章节或接口。

## 输出

单一 Markdown 接口文档（分片生成时是本次范围内的那些章节 / 接口）。

## 规范的优先级

1. `references/team-api-guidelines.md` —— **团队 HTTP 接口规范**。
   版本前缀、统一响应、错误码格式、分页 / 幂等、时间与金额格式、命名风格以它为准。
   它与 system prompt 的「固定默认约定」冲突时，**以本文件为准**（团队自己的约定优先）。
2. `references/writing-rules.md` —— 写作与可追溯要点：FR 追溯、两张表互斥、
   枚举穷举、示例可直接粘贴。
3. `references/history-weekly-report-api.md` —— 一份**真实产出**的接口写法示例。

## 示例怎么用

学它的**写法**：路径命名、请求 / 响应参数表的列怎么排、JSON 示例怎么组织、
错误码怎么引用。

⚠️ **不要照抄它的业务内容。** 那是另一个产品（群聊周报助手）的接口：
资源名、字段名、错误码前缀都必须来自本次的 PRD，与示例无关。

## 三条硬要求

1. **可追溯**：每个接口都要标 `PRD 来源`（`FR-xx`），且该编号必须真实存在于本次 PRD；
   找不到出处的接口不许造。
2. **规范内化为设计结果，不要逐段复制规范原文到输出。** 交付物是接口文档，
   不是规范说明书 —— 规范体现在你给出的路径、字段、错误码与示例里。
3. **PRD 里没给的东西不要补**：查不到出处就按 system prompt 的规则就地标 `[待确认]`，
   不要用邻近内容顶替。
