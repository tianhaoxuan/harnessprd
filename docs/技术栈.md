## 5. 版本口径、升级纪律与已知风险

**单一来源**：后端依赖只在 `backend/requirements.txt` 声明；本文档是它的解释与镜像。

**升级必须先跑**（顺序不能省）：

```powershell
cd backend
.venv\Scripts\python scripts\smoke_check.py                 # 1. 离线：配置/提示词/模型构造/路由
.venv\Scripts\python -m uvicorn main:app --port 8000        # 2. 另开终端
.venv\Scripts\python scripts\http_check.py http://127.0.0.1:8000
.venv\Scripts\python scripts\validate_prompts.py --recheck  # 3. 免费复查留档
```

**⚠️ 换了 LLM 模型或动了 LangChain 大版本 → 必须跑 `validate_prompts.py` 全量（7 次真实调用）。**
理由不是"保险起见"，是实测过：换 model 直接打破过一条已声明的设计假设（HANDOFF §4 坑 #14）。

**三套版本号独立演进，不要合并**（`会话持久化方案` §8.1）：

| 版本号 | 位置 | 管什么 |
| --- | --- | --- |
| `schema` | localStorage key + 信封 | 浏览器侧数据结构（不兼容**直接丢弃**，不写迁移链） |
| `form_version` | 服务端 `SessionState` | 表单题目定义（`questions_config.json`，语义化版本：加题=minor，删题/改 `id`=major） |
